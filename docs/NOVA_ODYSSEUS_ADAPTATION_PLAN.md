# Nova Odysseus Adaptation Plan

Generated by Nova's verified self-change engine.

## What Odysseus suggests Nova should copy/adapt

Odysseus is useful inspiration because it treats a local assistant as a full self-hosted AI workspace, not just a chat box. The most transplantable ideas for Nova are:

1. **Tool toggles and privileged-tool separation** — keep shell, file write, Python, email, calendar, MCP and model-serving actions behind explicit risk gates.
2. **Cookbook-style local model setup** — scan hardware, recommend fitting models, then provide one-click or one-command setup guidance.
3. **Deep research workspace** — gather sources, keep research runs inspectable, and produce a report rather than a loose answer.
4. **Model comparison mode** — send the same prompt to multiple local/API models and compare results blind before choosing a final answer.
5. **Documents-first workflow** — let the user edit real documents while Nova suggests targeted edits, summaries, CSV/Markdown/HTML transforms and checks.
6. **Memory and skills as visible assets** — allow import/export, review, disabling, and testing of memory/skills instead of letting them become hidden behaviour.
7. **Notes, tasks and scheduled agents** — keep a visible queue of future actions, reminders and agent jobs with clear run receipts.
8. **First-run/fresh-install diagnostics** — improve degraded-state reporting for model providers, search, email, calendar, Chroma/vector memory, and optional services.
9. **Mobile/PWA polish** — responsive layout, touch-friendly controls, installable UI and less desktop-only behaviour.
10. **Theme and visual customisation** — user-editable themes and clearer dynamic UI states.

## Recommended Nova transplant order

1. Verified self-change engine for low-risk, auditable changes.
2. Tool permission cockpit showing tool risk, enabled/disabled state and admin-only controls.
3. Hardware-aware model cookbook for Ollama, llama.cpp and optional API models.
4. Model comparison command for local model selection and answer confidence.
5. Research-run receipts with citations, source snapshots and synthesis reports.
6. Skill audit command that tests whether active skills help or inject bad behaviour.
7. First-run setup doctor with degraded-state explanations and fix plans.

## Guardrails for copying ideas

Nova should not blindly copy Odysseus code. Treat Odysseus as product/UX inspiration, then reimplement small Nova-native features with tests, rollback and release hygiene. Any privileged tool must require an explicit scope, a preview, a validation plan, and a receipt.
